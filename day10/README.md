## Part 1
Part 1 took a little bit of thought, but I opted to go with a binary approach to it since really the switches were either on or off. It seemed logical that the easiest way to go about handling this was by brute forcing since the search field was relatively manageable. Most of the logic hung around some pretty fundamental principles that helped me solve this relatively easily:

1. Pressing the same button twice cancels out the effect. So a button should never be pressed more than once.
2. Order doesn't matter. Don't need to press buttons in any order, just have to define what buttons need to be pressed.
3. So by the logic of the last two, pressing button **A**, then button **B**, then button **A** again is the same as just pressing button **B**.

With all that in mind, all I had to do was find the combination of button presses to accomplish the desired state. Since all I was doing was toggling states, I could basically just try every combination of button presses and at least one _should_ work. Then just find the smallest amount of button presses that successfully obtain the desired state.

## Part 2

Part 2 was where they unveiled what the "Joltages" meant, and it created an enormous branching search field to choose from. Now, instead of just toggling state, I'm instead incrementing a value to a specific _Joltage_ value. With the amount of Joltage values I had to obtain now being an integer I had to count to, it turned into "The amount of times I have to push a button to obtain this value is 250" or whatever that particular Joltage value was. Some had something like 11 Joltage values, most of which were in the triple digits. So that turned into "The amount of button presses would never be less than the highest Joltage value in the index, and the amount would also never be more than `256 * 190 * 45 * 143 * 94 * 202 * 140 * < snip >` ...and now we're in the neptillions. The branching search field became gargantuan.

 I initially tried to invalidate as many patterns as I could so I could chip away at the branches, and I really felt like I was getting somewhere with it because even with using depth-first-search to explore all possibilities and invalidating a bunch of possibilities through logical conclusions, I ran the script and sure enough it would actually solve the puzzles. Slowly, sure, but it still did it. I was so fed up with it that I just let it run its course because it was crunching through things slowly but steadily. I simply let it crunch away while I went to bed, hoping to wake up the next morning and get an answer. This attempt is stored in [buttoncount.go](lights/buttoncount.go) under `SolveCountDFS()`, in one of my many attempts at solving this piece.
